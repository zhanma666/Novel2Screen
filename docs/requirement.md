# Novel2Screen 需求分析

## 1. 文档依据

本文档依据根目录 `README.md` 中的项目描述与核心功能重新生成，用于约束后续的架构设计、数据 Schema 设计、后端接口开发和前端页面实现。

Novel2Screen 的产品定位是：基于大语言模型的小说影视化创作平台。系统围绕小说文本，完成解析、图谱构建、剧本改编、分镜规划、剧本审校、质量评估与 YAML 结构化导出。

## 2. 项目目标

1. 将 TXT、DOCX 小说文本自动解析为章节化结构。
2. 从小说中抽取人物、身份、关系、事件、地点与时间信息。
3. 构建人物关系图谱与故事知识图谱。
4. 根据图谱和用户配置生成不同影视风格的剧本。
5. 对生成或编辑后的剧本进行 AI 审校与质量评估。
6. 根据剧本生成分镜脚本。
7. 按统一 Schema 导出结构化 YAML 剧本文件。

## 3. 目标用户

| 用户类型 | 主要诉求 |
| --- | --- |
| 小说作者 | 将小说快速改编为影视剧本初稿 |
| 编剧 | 提取原著人物、事件与时间线，辅助改编创作 |
| 影视策划 | 快速评估故事结构与影视化潜力 |
| 分镜师 | 基于剧本获得初步镜头设计和分镜脚本 |
| 内容团队 | 获得统一、可审校、可导出的结构化剧本资产 |

## 4. 产品范围

### 4.1 MVP 必须支持

1. 小说上传与解析。
2. 人物关系图谱构建。
3. 故事图谱生成。
4. 多风格剧本改编。
5. AI 剧本审校。
6. 在线剧本编辑。
7. 分镜脚本生成。
8. 剧本质量评估。
9. YAML 格式导出。

### 4.2 暂不纳入首版

1. 自动生成成片视频。
2. 多人实时协同编辑。
3. 商业版权检测。
4. 支付、订阅和复杂权限系统。
5. 生产级大模型调度平台。

首版应优先打通“小说输入 -> 结构抽取 -> 剧本生成 -> 审校编辑 -> 分镜生成 -> YAML 导出”的完整链路。

## 5. 功能需求

### FR-01 小说上传与解析

系统应支持上传 TXT、DOCX 格式小说，并自动进行文本解析与章节拆分。

功能要求：

1. 支持 TXT 文件上传。
2. 支持 DOCX 文件上传。
3. 自动识别章节标题和章节正文。
4. 清理多余空行、页眉页脚、无效字符等噪声。
5. 保存原始文本与解析后的章节结构。
6. 解析失败时返回明确错误信息。

验收标准：

1. 用户上传合法 TXT 或 DOCX 后，可以看到章节列表。
2. 每个章节包含章节序号、章节标题和正文。
3. 不支持的文件类型会被拒绝，并给出提示。

### FR-02 人物关系图谱

系统应自动抽取小说中的人物、身份及人物关系，并生成可视化人物关系图谱所需的数据。

功能要求：

1. 抽取人物名称、别名、身份、简介和首次出现章节。
2. 抽取人物之间的关系类型。
3. 为关系保留证据来源，例如章节编号或原文片段。
4. 支持用户修正人物信息和关系信息。
5. 输出适合前端图谱渲染的节点与边数据。

验收标准：

1. 人物节点能展示名称、身份和简介。
2. 关系边能展示关系类型和关系说明。
3. 用户可以定位关系来源。

### FR-03 故事图谱

系统应自动提取人物、事件、地点与时间信息，构建故事知识图谱。

功能要求：

1. 抽取关键事件。
2. 抽取事件参与人物。
3. 抽取事件发生地点。
4. 抽取明确或推断的时间信息。
5. 建立人物、事件、地点、时间之间的关联。
6. 支持按章节顺序或故事时间线查看事件。

验收标准：

1. 每个事件包含摘要、参与人物、地点、章节来源和时间线顺序。
2. 故事图谱可作为剧本生成的输入上下文。
3. 用户可以查看事件与原文之间的映射关系。

### FR-04 多风格剧本改编

系统应支持电影、电视剧、短剧、动漫等多种剧本风格生成。

功能要求：

1. 用户可以选择剧本风格。
2. 用户可以配置目标篇幅、重点情节和改编倾向。
3. 系统根据故事图谱生成剧本结构。
4. 剧本应包含场次、场景、人物、动作描述和对白。
5. 生成内容应保留与原始章节或事件的关联。

验收标准：

1. 至少支持电影、电视剧、短剧、动漫四种风格。
2. 生成结果具有明确场次结构。
3. 每场至少包含场景信息、出场人物和剧本正文。

### FR-05 AI 剧本审校

系统应自动检查剧本中的角色一致性、时间线合理性、场景完整性和对白分布，并提供修改建议。

功能要求：

1. 检查角色称谓、身份、行为逻辑是否一致。
2. 检查事件顺序和时间线是否冲突。
3. 检查场景是否缺少地点、时间、人物或动作描述。
4. 检查对白占比是否异常。
5. 输出问题等级、问题位置、问题说明和修改建议。

验收标准：

1. 每条审校问题都能定位到具体场次或对白。
2. 审校结果包含严重程度。
3. 审校建议具有可操作性。

### FR-06 人机协同创作

系统应支持用户在线编辑剧本，并实时或准实时更新审校结果与质量评估信息。

功能要求：

1. 支持编辑场次标题、场景描述、动作描述和对白。
2. 支持新增、删除、调整场次。
3. 支持用户手动触发重新审校。
4. 支持在编辑后更新质量评分。
5. 保存剧本版本信息，避免误操作造成内容丢失。

验收标准：

1. 用户修改剧本后，保存结果可再次打开。
2. 修改后的内容可以重新审校。
3. 质量评估结果随最新剧本内容更新。

### FR-07 分镜脚本生成

系统应根据剧本自动生成镜头设计、景别、运镜方式、光线建议及镜头时长。

功能要求：

1. 按场次生成分镜。
2. 每个分镜镜头包含镜头编号、画面描述、景别、运镜、光线和预计时长。
3. 分镜镜头应映射到对应剧本场次。
4. 用户可以编辑或重新生成单场分镜。

验收标准：

1. 每个场次至少可生成一组镜头。
2. 每个镜头字段完整。
3. 分镜总时长可以汇总统计。

### FR-08 剧本质量评估

系统应从完整性、一致性、场景连续性等多个维度对剧本进行评分。

功能要求：

1. 输出总分。
2. 输出维度评分。
3. 维度至少包含完整性、一致性、场景连续性、对白分布。
4. 每个维度应包含评分说明。
5. 评分结果应与审校问题关联。

验收标准：

1. 用户能看到总分和各维度分数。
2. 用户能理解扣分原因。
3. 修正剧本后可以重新生成评分。

### FR-09 YAML 格式导出

系统应按照统一 Schema 导出结构化 YAML 剧本文件。

功能要求：

1. 导出项目元信息。
2. 导出原文解析摘要。
3. 导出人物、关系、事件和故事图谱信息。
4. 导出剧本场次、对白和动作描述。
5. 导出分镜脚本。
6. 导出审校结果和质量评分。
7. 导出前进行 Schema 校验。

验收标准：

1. 导出的 YAML 文件结构稳定。
2. YAML 文件可被系统重新读取。
3. 字段缺失或类型错误时能提示校验失败原因。

## 6. 非功能需求

### NFR-01 可维护性

系统应按模块拆分小说解析、图谱构建、剧本生成、审校、分镜和导出能力，避免核心逻辑耦合。

### NFR-02 可扩展性

剧本风格、审校规则、质量评分维度和 YAML Schema 应支持后续扩展。

### NFR-03 模型可替换性

大语言模型调用应通过统一适配层封装，业务逻辑不应直接绑定单一模型供应商。

### NFR-04 可追溯性

系统应保存 AI 生成内容的来源信息，包括原始章节、关联事件、提示词版本、模型名称和生成时间。

### NFR-05 性能

长篇小说处理应支持分章节、分块和异步任务，避免单次请求处理整部小说导致超时。

### NFR-06 数据安全

小说原文、剧本和分镜属于用户创作资产，不应在日志中明文输出完整正文。

### NFR-07 用户体验

耗时任务应展示状态，例如等待中、处理中、成功、失败，并在失败时展示可理解原因。

## 7. 核心数据对象

| 对象 | 说明 |
| --- | --- |
| Project | 小说影视化项目 |
| SourceDocument | 上传的原始小说文件 |
| Chapter | 解析后的章节 |
| Character | 人物信息 |
| Relationship | 人物关系 |
| StoryEvent | 故事事件 |
| StoryGraph | 人物、事件、地点、时间的知识图谱 |
| Script | 剧本版本 |
| Scene | 剧本场次 |
| Dialogue | 对白 |
| Shot | 分镜镜头 |
| ReviewIssue | 审校问题 |
| QualityScore | 质量评分 |
| ExportFile | 导出的 YAML 文件 |

## 8. 主要业务流程

1. 用户创建项目。
2. 用户上传 TXT 或 DOCX 小说。
3. 系统解析文本并拆分章节。
4. 系统抽取人物、身份和人物关系。
5. 系统抽取事件、地点和时间信息。
6. 系统生成人物关系图谱和故事图谱。
7. 用户选择剧本风格并配置生成参数。
8. 系统生成剧本初稿。
9. 用户在线编辑剧本。
10. 系统执行 AI 审校并输出修改建议。
11. 系统生成剧本质量评分。
12. 系统根据剧本生成分镜脚本。
13. 用户导出 YAML 格式剧本文件。

## 9. 优先级规划

| 优先级 | 功能 |
| --- | --- |
| P0 | 小说上传与解析、剧本生成、YAML 导出 |
| P1 | 人物抽取、故事事件抽取、AI 审校、在线编辑 |
| P2 | 人物关系图谱、故事图谱、质量评估 |
| P3 | 分镜生成、版本管理、复杂图谱可视化 |

## 10. 主要风险

1. 长篇小说上下文过大，直接输入模型会超过上下文限制。
2. AI 抽取人物和事件可能出现漏提、误提和关系混淆。
3. 剧本改编质量依赖提示词设计、结构化上下文和模型能力。
4. 如果 YAML Schema 不稳定，后续导入、导出和分镜工具都会受影响。
5. 审校与质量评分需要可解释依据，否则用户难以信任结果。
